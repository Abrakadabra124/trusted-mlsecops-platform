# Статус и границы доказательств

Дата snapshot: **2026-10-06**. Стадия: **R0 research/design**.

## Подготовлено

- Изучены статья PT, 11 страниц предоставленного PDF и изображение ML lifecycle; права третьих лиц сохранены через ссылки/атрибуцию без републикации оригиналов.
- Составлен реестр из 24 источников/записей evidence, включая локальный PDF и отдельные code/evidence/CI ссылки baseline.
- Сопоставлены DevSecOps baseline, отсутствующие ML-контроли, P0-долги и ограничения локального стенда.
- Подготовлены карта продукта, архитектура, 14 сценариев угроз, 18 критериев приёмки, 12-недельный план и 24 задачи.
- Реализован только документационный валидатор и GitHub Actions workflow для него.

## Что не реализовано

Training pipeline, MLflow deployment, модели, dataset manifests, production verifier, inference API, poisoning/evasion experiments, drift monitoring, ML restore и M01-M18. Их описания и численные thresholds - требования к будущему результату. Все T01-T24 открыты.

## Что проверяется отдельно

Локальная команда `python scripts/check_docs.py` подтверждает структурную связность документов и ограниченные publication checks. CI повторяет её на опубликованном commit. Актуальный результат смотрите в [GitHub Actions](https://github.com/Abrakadabra124/trusted-mlsecops-platform/actions); наличие workflow-файла само по себе не доказывает успешный запуск.

В исходной платформе через GitHub API проверен успешный [run 37211112894](https://github.com/Abrakadabra124/enterprise-devsecops-platform/actions/runs/37211112894). Локальные инфраструктурные результаты от 2026-10-04 используются как историческое evidence, не как новые измерения 2026-10-06.

## Ограничения исследования

Не измерялись актуальные ресурсы PC/кластера, не выбирался настоящий бизнес-dataset, не выполнялись новые security/ML эксперименты, не проверялось соответствие применимому законодательству. Веб-документация `latest` может измениться. Отдельные недоступные страницы обозначены в [реестре](docs/sources.md), выводы не основаны на их предполагаемом содержимом.

## Следующий допустимый шаг

Новая реализационная цель по T01-T02: подтвердить scope, inventory, compatibility, разрешённый путь работы с foundation и данные. Не начинать со скачивания всей экосистемы и не менять статус проекта на production-ready после одной установки.
