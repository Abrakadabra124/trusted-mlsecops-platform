# Как использованы предоставленные материалы

## 1. Статья Positive Technologies

Статья Светланы Газизовой связывает безопасность данных и моделей с существующим DevSecOps-процессом, выделяет утечки, манипуляции и нарушение работы бизнеса. Полезный вывод для проекта: защищать нужно весь путь модели, а не только HTTP API. [Источник S01](sources.md#s01)

Для нашей архитектуры этого недостаточно: нужны конкретные противники, проверяемые полномочия, независимая оценка и негативные тесты. Утверждения статьи 2024 года о нормативном контексте не переносятся автоматически на 2026 год; это не юридическое заключение. Приведённые в статье рыночные проценты не использованы как требования или доказательства.

## 3. Схема MLOps: Eternal Knot

На изображении связаны циклы Data, ML, Dev и Ops. Мы используем эту идею, чтобы не завершать работу на deploy: мониторинг возвращает проверенные наблюдения в управление данными и требованиями. Собственные схемы в этом репозитории показывают дополнительные trust boundaries и точки запрета выпуска. [Авторский первоисточник S03](sources.md#s03)

| Цикл | Дополнение в проекте |
| --- | --- |
| Data | Источник, разрешение, контракт, карантин, подпись версии |
| ML | Изолированный trainer, независимый evaluator, тесты манипуляций |
| Dev | Контроль зависимостей, безопасные форматы, provenance и policy tests |
| Ops | Верификация при старте, метрики поведения, revocation, recovery |

## Итог сопоставления

Курс даёт карту MLOps-компетенций, схема показывает непрерывность цикла, статья объясняет необходимость защиты. Конкретные проектные решения проверены по первоисточникам и отделены от доказательств действующей платформы. Новый проект не является копией курса, официальным продуктом указанных организаций или сертификатом их соответствия.
