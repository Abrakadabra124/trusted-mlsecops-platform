# Dataset card: synthetic-release-lab-v1

Статус: реализован synthetic developer dataset. Никаких реальных релизов, сотрудников, клиентов или персональных данных. Data owner в lab - владелец локального стенда в роли curator.

## Генерация и контракт

20 000 независимых синтетических entities; seed 24017. Split фиксирован по непересекающимся ID: 14 000 train, 3 000 validation, 3 000 final holdout. Это не доказательство temporal/group split на реальных production-событиях. Реальный label horizon пока не задан.

В каждой строке обязательны только `entity_id`, `features`, `label`. ID - уникальный неотрицательный integer, label - строго integer 0/1, не boolean. Все шесть features - конечные числа от 0 до 1, в следующем порядке:

| Поле | Лабораторная интерпретация |
| --- | --- |
| change_size | Нормированный размер изменения, не количество строк кода |
| failed_checks | Нормированная доля неуспешных проверок |
| dependency_changes | Нормированная интенсивность изменений зависимостей |
| test_coverage | Условное покрытие, не измеренное покрытие настоящего проекта |
| change_entropy | Условная неоднородность изменения |
| prior_failure_rate | Условная историческая доля ошибок |

Features получаются из независимых uniform samples с округлением до шести знаков. Bernoulli label задаётся вероятностью от заранее заданной линейной logit-функции. Формула явно находится в `mlsecops/datasets.py`; она намеренно создаёт проверяемую задачу для Logistic Regression. Модель не обнаруживает настоящую зависимость реальных release failures.

## Доверие и хранение

Source approval подписан отдельным lab curator, имеет purpose `synthetic-lab` и срок 30 дней. Manifest подписывает digest/размер/число строк каждого split, feature order и policy/source bindings. Dataset ID - hash manifest, а не путь, присланный моделью.

Файлы остаются в игнорируемой `.runtime/approved/`. Worker получает только явно переданный train или feature batch, не каталог approved/keys. Хеши detects byte tampering, но не доказывают корректность семантически допустимых labels. Смена approval может изменить dataset ID даже при одинаковых generated bytes.

Реализованы negative component checks типов, пропусков, лишних полей, duplicate IDs, NaN/range, expiry, unknown source, tamper/missing file и cross-split ID validation. DVC и отдельные Kubernetes storage identities ещё не готовы; полного M02-M03 pass не заявляется.
