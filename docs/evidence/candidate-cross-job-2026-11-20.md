# Квалификация передачи исходного кандидата и восстановления M11/M12

20 ноября 2026 года GitHub Actions выполнил квалификацию на свежем публичном `ubuntu-24.04` в проверочной ветке `qualify/candidate-cross-job`. Исходный коммит `e48a7dbb566e1cfc94f57eb207910c2250f4226d`. Python 3.12.15, зависимости из `uv.lock`. Попытка 1 завершилась успешно. [Исходный код](https://github.com/Abrakadabra124/trusted-mlsecops-platform/tree/e48a7dbb566e1cfc94f57eb207910c2250f4226d), [журнал запуска](https://github.com/Abrakadabra124/trusted-mlsecops-platform/actions/runs/44782409403).

## Что проверялось

- На подписанном тестовом кандидате два штатных потребителя раскрыли один исходный архив. У них разные каталоги и идентификаторы рабочих пространств. Для пути serving проверены исходные M02/M03/M07 и validation split.
- Независимый ключ издателя, подпись Ed25519 и AES-GCM привязывают управляющую запись к исходному запуску, попытке, образу, proposal и четырём конкретным файлам. Владение симметричным ключом и доступ к записи в хранилище сами по себе не дают возможности выпустить подменённую запись от имени издателя.
- Проверены отказ при неверном manifest, архиве, доверенном ключе, завершённой попытке, изменившейся приватности и потере обязательного временного запаса. Отдельный тест проверяет подпись сохранённой управляющей записи после окончания срока допуска.
- Обработчик M11/M12 использует отдельный журнал владельца ресурсов потребителя, штатные проверки и повторное чтение сохранённых свидетельств после удаления временного представления.
- GitHub Release API, сеть, SQL и Kubernetes в этих тестах представлены управляемыми тестовыми реализациями. Реальные криптографические примитивы, файловые границы и штатные читатели выполнялись на Linux. Приёмочный запуск настоящего ML-кандидата требует отдельных полномочий и приватных свидетельств.

## Воспроизведение и следующая граница

В чистом checkout этого SHA запустить команды из шага `Verify both consumers and failure paths with controlled storage` в опубликованном workflow. Код проверяет запрет пропусков и обе метрики каждого модуля. [Workflow](https://github.com/Abrakadabra124/trusted-mlsecops-platform/blob/e48a7dbb566e1cfc94f57eb207910c2250f4226d/.github/workflows/candidate-cross-job.yml), [порядок передачи](../operations/campaign-handoff.md), [восстановление M11/M12](../operations/ci-shared-job.md).

Для настоящего запуска остаются обязательными отдельные права чтения и записи на приватный репозиторий, сохраняемый за пределами runner журнал, независимая проверка окончания попытки и сохранности первичных свидетельств. Готовность release требует штатных результатов на одном кандидате, независимых M22 и финального M18.
