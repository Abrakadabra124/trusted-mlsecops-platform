## От требования к реализации

Исходные Syft SBOM сохраняют 89 `UNKNOWN`, семь runner pseudo-versions и четыре
известные записи `k8s.io/kubernetes@v1.36.4`. Они не переписываются. Отдельный
[реестр](../../scripts/image_kubernetes_aliases_registry.json) содержит 100
привязок к исходным доказательствам и опубликованным модулям. Его полный SHA-256
закреплён в [проверяющем коде](../../scripts/image_kubernetes_aliases.py).

Реестр основан на [первичном сравнении исходников](kubernetes-module-mapping-2026-11-20.md),
а не на вычислении версии модуля из тега образа. Два вспомогательных модуля
участвуют в доказательстве зависимостей, но не добавляют лишние координаты сканирования.
Config reference и наблюдаемый manifest reference различаются явно.

[Runner](../../scripts/image_kubernetes_scans.py) допускает только весь фиксированный
набор из 28 координат. Он проверяет входы до запуска, использует тот же read-only
снимок базы Grype, отключённую сеть и существующие ограничения контейнеров.
JSON, CycloneDX и trace поступают из одной команды. После каждого запуска
подтверждается отсутствие контейнера по его точному ID.

[Reader](../../scripts/image_go_supplemental_contract.py) проверяет PURL, единственный
компонент CycloneDX, каждую находку, trace поиска, завершение matching, свежесть
базы и код выхода. Пустого списка находок недостаточно. Для High/Critical
допускается только конкретное сообщение о пороге из закреплённого исходного
кода Grype, а не произвольная ошибка с exit 2.

При объединении повторно читаются исходные SBOM/report и все 28 дополнительных
результатов. Изменение байтов, базы, реестра или состава набора вызывает отказ.
Исходные находки остаются в результате, включая C/H/U и raw versions.
High/Critical сохраняют `fail`; при их отсутствии Unknown сохраняет `inconclusive`.
Число occurrences и число уникальных уязвимостей учитываются раздельно.

Основной [аудитор](../../scripts/image_audit.py) выполняет detection controls до
дополнительных сканирований. [Проверка покрытия](../../scripts/image_scope.py)
сверяет полную привязку и объединённые результаты; одного имени профиля или
флага `sbom_validated` недостаточно. Полный runtime denominator сохраняется.

## Исправления после review

Независимый внутренний reviewer воспроизвёл два дефекта на контролируемых
фикстурах. Оба исправлены до hosted запуска и повторно проверены:

- Cleanup больше не ищет CID рекурсивно. Он читает только 40 точных
  host-owned receipt paths. Файл чужого CID в writable output не даёт права
  обращаться к этому контейнеру или удалять его.
- Join снимает только диагностику отсутствующих версий Kubernetes. Посторонняя
  ошибка, несовпадение исходного решения или добавленный `reason` запрещают
  успешный join/coverage. Дополнительный скан не исправляет чужую ошибку аудита.

Повторная проверка reviewer: 27/27 targeted tests прошли, замечания закрыты.
Это внутренний code review, не независимые человеческие challenges M22.

## Пределы доверия

- Константы реестра являются проверенной конфигурацией. Изменение источников,
  recipes, допустимых path deltas или образов требует нового review.
- Хеши и повторное чтение не превращают отчёты в подписанные attestations.
  Администратор runner остаётся доверенным субъектом.
- Сопоставление выполняется для целого модуля. Compiler equivalence,
  reachability и отсутствие неизвестных уязвимостей не заявляются.
- Полное воспроизведение старых findings требует сохранённого снимка базы.
  Новая свежая база может дать другой результат.
- Private raw reports, database, trace и исходные локальные proof packets
  не публикуются. В репозиторий входят код, фиксированные публичные привязки
  и закрытая по составу итоговая проекция.

## Источники контракта

Формат optional arrays подтверждён в
[Grype v0.120.1 document.go](https://github.com/anchore/grype/blob/v0.120.1/grype/presenter/models/document.go).
Точное threshold message и отсутствие final summary на соответствующем пути
проверены в [errors.go](https://github.com/anchore/grype/blob/v0.120.1/grype/grypeerr/errors.go)
и [vulnerability_matcher.go](https://github.com/anchore/grype/blob/v0.120.1/grype/vulnerability_matcher.go).
Это первичные исходники поддерживаемой версии, а не восстановление текста
ошибки из предыдущего диагностического CI-прогона.

Пустое `Fix.State` является допустимым значением строкового поля закреплённой
[модели Grype](https://github.com/anchore/grype/blob/v0.120.1/grype/presenter/models/vulnerability.go).
Reader сохраняет это значение и саму находку; оно не означает наличие исправления
и не изменяет решение High/Critical/Unknown.
