## Как воспроизвести

Исходные опубликованные строки отдельно проверены на Windows в чистом checkout ревизии `09518db`. Из ранее завершённого шага GitHub Actions взят `M18_DELIVERY_SHA256=734f3012277266518e8ec642be86e5908082c373b7a39e48473f4d9b6b122241`. Штатная команда `python -m mlsecops.acceptance --gate M18 --state <каталог-копии> --output <отчёт.json>` воспроизвела 12 совпадений и код 2. Изменение одного байта в копии метрики M13 при тех же хешах дало 11 совпадений, M13 в `unavailable` и код 1. После возвращения исходных байтов повтор снова дал 12 совпадений и код 2. Это проверка целостности сохранённых отчётов. Она выполняется офлайн и не требует запуска инфраструктуры.

В GitHub Actions откройте workflow **T20 scheduled backup and independent recovery** и выберите ревизию через ветку, указывающую на нужный коммит. Для этого пути параметр `serving_gate` равен `M13`. Нужен одноразовый Linux runner лабораторного профиля. Дождитесь проверки удаления кластера и шага **Identify missing evidence for final M18 acceptance**. Новая попытка создаёт собственные идентификаторы, подписи и хеши отчётов. Сверяйте их между шагами одной попытки.
