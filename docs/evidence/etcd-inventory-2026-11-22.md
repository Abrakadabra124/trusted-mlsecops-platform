## Что изменилось в полном аудите после перехода

В чистом запуске `45018971253` на `6abe6c7` опись etcd содержала 148 записей Go и шесть Debian. Для семи внутренних Go-модулей сканер проверил версии на той же базе, что и исходный образ. Все семь сканов подтвердили свою идентичность и очистку. В результирующем отчёте сохранились все три исходных совпадения Medium по `GHSA-q7gw-24fr-5p69`. Компонент получил `pass`, Critical, High и Unknown равны нулю. В предыдущем аудите штатного образа оставались две записи Unknown для `golang.org/x/crypto`.

Покрытие приложений выросло с 11/14 до 12/14. Открыты Cilium agent и узел kind. Для платформы общий статус `fail`, 389 уникальных advisory. Из них 24 получили оценку Critical, 141 получили High хотя бы в одном совпадении. Один идентификатор может встретиться с разными оценками у разных поставщиков. Базы Grype в двух полных запусках различаются. Парное измерение исправления etcd на одной базе записано отдельно в квалификации сборки.

Первичный отчёт совпал с повторно опубликованным JSON после канонизации, SHA-256 `b2d0a38f8cfa41e62d818d53b250542d6777006be829b8234b207dcf82554d20`. Для использованного файла базы Grype SHA-256 равен `08b302c006875468fc087630ba33be9d814a2585047ddc874c8cd7a8bfab0d1b`. После отказа аудита проверено удаление кластера и узла. [Предыдущий аудит](https://github.com/Abrakadabra124/trusted-mlsecops-platform/actions/runs/44959047516), [новый полный аудит](https://github.com/Abrakadabra124/trusted-mlsecops-platform/actions/runs/45018971253).

## Переключение etcd и откат

На `b891940` одноразовый Kubernetes-кластер успешно выполнил переход с исходного etcd на просканированный кандидат и обратно. Значение `imageRef` работающего контейнера указывало на импортированный OCI-индекс. Код прочитал содержимое по digest, проверил SHA-256, выбрал манифест Linux AMD64 и сопоставил его config с отчётом Grype. У кандидата подтверждён config `sha256:f785c01e22758460d916bdbb6300c1cc383c0a17a97c95408d606b7cb9630898`. Во всех трёх состояниях сервер вернул версию 3.6.17 и одинаковый идентификатор лидера. После переключения перечитан первый ConfigMap и записан второй. После отката у обоих сохранились исходные UID и содержимое. Исходный манифест восстановлен побайтово. Отдельный шаг подтвердил отсутствие кластера и узла. Опыт подтверждает совместимость замены в этом профиле. Штатный запуск из `infra/kind.yaml` по-прежнему использует официальный образ. [Запуск с переключением и откатом](https://github.com/Abrakadabra124/trusted-mlsecops-platform/actions/runs/44960577583), [ранбук](../operations/image-audit-troubleshooting.md).

В первой попытке на `3934071` исходный сервер отвечал, в API был записан и прочитан ConfigMap. При проверке обновлённого Pod команда `crictl inspecti` не смогла прочитать образ по значению `imageRef` работающего контейнера. Проверка отклонила кандидат. При откате подтвердились исходный config, прежний лидер и исходный ConfigMap с тем же UID. Кластер удалён. [Неуспешная попытка и откат](https://github.com/Abrakadabra124/trusted-mlsecops-platform/actions/runs/44959300356).
