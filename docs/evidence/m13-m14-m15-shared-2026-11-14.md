фактические объекты Kubernetes и отсутствие удаляемого кластера перед следующим

После очистки verifier перепроверил подписи исходных материалов, три разных permit,
полный аудит фактического M13, контрольное окно CLI, закрытые окна сервисов, мониторинг,
обратную связь, измерения M14 и доставки M15. Для каждого опубликованного поля
`report` отдельно пересчитан `sha256(canonical(report) + LF)`, проверены
уникальные критерии, их результаты и общие входы.

разрешения ограничены экспериментом. Общая приёмка M18 и эксплуатационный
допуск остаются открытыми, `release_ready=false`.
