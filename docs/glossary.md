# Краткий словарь

| Термин | Что это и какую роль играет |
| --- | --- |
| ML (Machine Learning) | Машинное обучение: параметры модели определяются по данным, поэтому изменения dataset могут изменить поведение без нового кода. |
| MLOps | Организация повторяемого обучения, версий, доставки и сопровождения моделей. |
| MLSecOps | Добавление управления рисками и security controls во весь ML lifecycle, включая данные и обучение. |
| DevSecOps | Совместная инженерия разработки, безопасности и эксплуатации; здесь это существующая основа source/container/infrastructure gates. |
| CI / CD / CT | Continuous Integration, Delivery/Deployment, Training: автоматизированные проверки изменений, доставка и обучение. Автоматическое обучение не означает автоматического допуска в production. |
| Dataset / labels | Набор примеров и целевые значения. Label provenance показывает, кто и как установил правильный ответ. |
| Holdout | Отложенная проверочная выборка, не используемая для обучения и обычного подбора параметров. Доступ к ней ограничен, иначе оценка перестаёт быть независимой. |
| Leakage | Попадание информации из будущего или проверочной выборки в обучение. Создаёт завышенные метрики, не обязательно является атакой. |
| Poisoning / backdoor | Манипуляция обучением; backdoor меняет поведение на специальных триггерах, сохраняя внешне нормальное качество. |
| Evasion | Изменение входа во время использования модели с целью получить ошибочное решение в рамках заданных возможностей атакующего. |
| Lineage / provenance | Связь артефактов и история их происхождения. В проекте - путь от источника и commit до конкретного run, модели и релиза. |
| SHA-256 / digest | Криптографический хеш содержимого. Обнаруживает изменение bytes, но сам не устанавливает честность источника. |
| Signature / attestation | Подпись и подписанное утверждение о материалах/процессе. Требуют проверки разрешённой идентичности и политики доверия. |
| DVC | Data Version Control: версии файлов данных и зависимостей ML-пайплайна рядом с Git metadata. Не заменяет подписи и права доступа. |
| MLflow | Tracking экспериментов и каталог моделей. Не должен один определять production approval через изменяемый alias. |
| ONNX / ONNX Runtime | Open Neural Network Exchange - формат вычислительного графа; Runtime исполняет этот граф. Не делает недоверенную модель автоматически безопасной. |
| FastAPI / Pydantic | Python API framework и проверка структурированных данных. Используются для контрактов запросов и ответов. |
| Pandera | Проверка схем и ограничений табличных данных; дополняет, а не дублирует API validation. |
| Kubernetes / kind | Оркестрация контейнеров; kind запускает Kubernetes nodes как контейнеры для локального стенда. Несколько kind-node на одном ПК не дают независимую HA. |
| RBAC / service account | Role-Based Access Control и identity workload. Определяют разрешённые действия, но требуют проверки storage/network permissions отдельно. |
| Cilium / Kyverno | Сетевые политики и policy admission в Kubernetes. В baseline используются для контроля связи и запрещённых workload configurations. |
| Flux / GitOps | Reconciliation состояния кластера с versioned desired state. Digest и approval должны быть проверены до изменения desired state. |
| IaC / Terraform | Infrastructure as Code и инструмент декларативного управления ресурсами. Позволяют проверять изменения инфраструктуры как код. |
| SOPS / age | Шифрование configuration secrets и используемый инструмент/формат ключей. Расшифрованные значения не помещаются в публичный Git. |
| OCI / S3 | Стандарты container artifacts и API объектного хранилища соответственно. Наличие object storage не означает неизменяемость или безопасный IAM. |
| SBOM / ML-BOM | Software / Machine Learning Bill of Materials: состав программных и ML-компонентов. Инвентаризация не заменяет доказательство происхождения. |
| Cosign / Sigstore | Инструменты подписания и проверки артефактов и подписанных утверждений. Политика определяет, каким identity/issuer можно доверять. |
| OIDC / KMS / TLS | OpenID Connect для identity, Key Management Service для управления ключами, Transport Layer Security для защиты канала. Не считаются внедрёнными в локальном исследовательском проекте. |
| TOCTOU | Time-of-check to time-of-use: объект может измениться между проверкой и использованием. Loader должен проверять именно те bytes, которые загрузит. |
| OOD / abstain | Out-of-distribution и отказ модели от уверенного ответа. Наши range checks дают ограниченный abstain, не универсальное распознавание неизвестных данных. |
| AUPRC / ASR | Метрика precision-recall качества и attack success rate. Всегда указывать классы, выборку, denominator и неопределённость. |
| Drift / PSI | Изменение распределений и один из его статистических индикаторов. Drift сам по себе не доказывает атаку или падение качества. |
| Prometheus / Grafana / Evidently | Сбор временных метрик, визуализация и расчёт ML/data reports. Каждый обслуживает отдельный слой наблюдения. |
| SLO / SLA | Цель качества сервиса и договорное обязательство. Короткий benchmark не доказывает месячную доступность. |
| RTO / RPO / DR | Время восстановления, допустимая потеря данных по времени и disaster recovery. Требуют проверки конечного работающего состояния. |
| LLM / RAG | Large Language Model и Retrieval-Augmented Generation: языковая модель и дополнение её контекстом из поиска. Это отдельный будущий профиль угроз. |
| ADR | Architecture Decision Record: записанное решение с альтернативами, последствиями и условиями пересмотра. |
