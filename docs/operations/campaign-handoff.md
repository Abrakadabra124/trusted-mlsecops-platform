# Передача исходного кандидата между заданиями

Процедура относится к неделе 13, T21. Издатель готовит один кандидат и записывает четыре зашифрованных файла в приватный репозиторий. Получатели проверяют происхождение пакета и открывают свой временный рабочий каталог. Код рассчитан на стандартный публичный GitHub-hosted runner с ресурсами исходного профиля. Приватными остаются данные, модель, файлы состояния, их хеши, идентификаторы приватных файлов и журнал восстановления.

## Действия издателя

1. Проверить чистый checkout, идентичность исходного образа, владельца запуска, номер попытки и роль задания. Подготовить исходное хранилище и записи предыдущих этапов. Для приватных операций использовать отдельную пару разрешений из [процедуры доступа](campaign-access.md).
2. Передать проверенный source и приватный журнал в `ci_campaign_publish.publish_original`. Функция проверяет принадлежность исходных ресурсов, завершает работу собственного подготовительного кластера и вызывает [подготовку единственного кандидата](ci-campaign-producer.md). Штатные адаптеры формируют пакеты для M11/M12, M13, исходных отчётов M02/M03/M07 и validation split.
3. Остановить исходный SQL через штатный обработчик. Издатель проверяет владельца контейнера и фиксирует хеш наблюдения об остановке. После записи в приватное хранилище он повторно проверяет остановку и идентичность исходного образа и checkout. Это наблюдение относится к машине издателя.
4. После загрузки четырёх файлов издатель подписывает запись с точными идентификаторами, размерами и SHA-256, фазой потребления, исходным proposal, владельцем и адресом приватного релиза. Закрытый одноразовый ключ Ed25519 удаляется вместе с временным каталогом. Подписанная запись шифруется AES-GCM отдельным ключом, выведенным по HKDF-SHA256 из ключа передачи. Открытый проверочный ключ предназначен для передачи через доверенный выход задания издателя. Хранилище не определяет этот ключ.
5. При каждом подтверждённом изменении хранилища вызывается `checkpoint`. Перед отправкой управляющей записи он также фиксирует открытый ключ издателя и хеши четырёхфайловой квитанции и готовой шифрованной записи. Оператор с доверенной копией журнала может вызвать `verify_retained_control` и после окончания окна. Функция подтверждает подпись сохранённых байтов и возвращает только логическое значение. Для допуска получателя действует прежнее временное окно. Для настоящего запуска обработчик должен записывать журнал в приватное место, доступное после потери runner. Полный результат `publish_original` содержит приватную квитанцию и не подходит для вывода в Actions log.

## Действия получателя

Вызвать `ci_campaign_handoff.open_consumer` с ролью `shared` или `serving`, клиентом только для чтения, исходным ключом доверия и ожиданиями из доверенного контекста запуска. Вначале получатель проверяет подпись управляющей записи и соответствие репозиторию, run ID, попытке и исходному образу. Затем сверяет точные release asset ID, размер и хеш. Обработка файла начинается только после этих проверок.

Получатель `shared` материализует пакет M11/M12. Получатель `serving` открывает отдельный рабочий каталог того же кандидата, присоединяет проверенные исходные отчёты и получает зашифрованный validation split для штатного импорта. Оба используют закрытый ключ исходного доверенного реестра, переданный независимым каналом. Файлы временного представления удаляются при выходе из контекста, включая исключения. Перед выходом вызывающая сторона должна завершить очистку собственных SQL и Kubernetes-ресурсов и сохранить необходимые первичные свидетельства.

## При отказе

| Наблюдение | Действие оператора | Условие продолжения |
| --- | --- | --- |
| Получатель отказал до открытия каталога | Сверить исходное задание, attempt, checkout, image ID и открытый ключ из зависимости jobs. Проверить доступ чтения и совпадение приватного release ID с квитанцией. | Подтверждён исходный издатель и доступен точный набор файлов. |
| Срок proposal или передачи истёк | Завершить попытку, сохранить имеющиеся первичные свидетельства и проверить очистку. | Для нового запуска подготовлен новый исходный кандидат. Доказательства предыдущей попытки остаются привязаны к ней. |
| После прерывания остался приватный тег, релиз или отдельный файл | Использовать приватный журнал и процедуру [очистки принадлежащих запуску объектов](private-assets.md). При неоднозначном владении сохранить состояние для оператора. | Проверены точные ID, конечный статус заданий, сохранившиеся первичные данные и фактическое отсутствие удалённых объектов. |
| Появилось расхождение в архиве, подписи или validation | Зафиксировать только этап и тип отказа. Сверить исходный пакет и приватную квитанцию через доверенные каналы. | Обычный проверяющий код принял исходные байты в исходном временном окне. |

## Воспроизведение без инфраструктуры

Из чистого checkout с зависимостями `uv.lock` выполнить

```console
uv run --locked python -B -W error -m unittest scripts.ci_campaign_control_qualification scripts.ci_campaign_handoff_qualification scripts.ci_campaign_publish_qualification
```

Тесты используют настоящие подписи, шифрование, один контролируемый кандидат и штатные читатели. Хранилище GitHub и наблюдения SQL в этих проверках представлены тестовыми реализациями. Приёмка M11 и всего R1 требует первичных результатов одного реального запуска и проверки восстановления.
