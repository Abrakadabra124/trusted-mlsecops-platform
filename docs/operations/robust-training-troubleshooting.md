# PB-19 / RB-37: robust training без ложного pass

Владелец: model reviewer и platform operator. Область: synthetic CPU research, не production-инцидент. [Frozen protocol](../robust-training-protocol.md) не разрешает менять бюджет атаки или baseline автоматически. Актуальные outcomes находятся в [STATUS](../../STATUS.md).

## Что решаем

Предыдущий baseline потерял 88 true positives на разрешённых evasion probes, recall drop 0.07184 при лимите 0.05. Domain-support abstain не защищает от изменений внутри support. Новый эксперимент проверяет обучение с worst-case loss: SciPy решает ограниченную задачу оптимизации, sklearn хранит scaler/classifier, ONNX переносит модель в изолированный inference worker. Это исследование mitigation, не готовая защита всех моделей.

При реализации действительно встретился `source_lock_mismatch_explicit_update_required` до запуска workers. Причина установлена: явное объявление SciPy в dependencies изменило uv.lock, хотя версия уже была установлена транзитивно. Generated output перепроверен побайтно, обновлена только provenance-привязка uv.lock в data.lock. Ошибка сохранена в private log; данные и thresholds не менялись. Отключать validate_lock нельзя.

## RB-37: read-only диагностика

```powershell
$report = Get-Content .runtime/robust-training-replay-20261013/evidence/robust-training.json -Raw | ConvertFrom-Json
$report | Select-Object status,execution_status,reason,campaign_id,parity,optimization,clean_ap_loss,worker_executions,primary_reconciliation | ConvertTo-Json -Depth 8
git diff -- pyproject.toml uv.lock data.lock
```

1. `execution_status=complete` и reconciliation pass подтверждают исполнение, не статистическую приёмку. Проверить все три probe outcomes обеих моделей, особенно candidate recall drop и clean AP loss. Нельзя выбирать лучший seed, скрывать known regression или заменять denominator.
2. `robust_training_solver_failed` означает неуспех solver/некорректные coefficients. `robust_training_convergence_unproven` означает, что повторно рассчитанный objective/projected gradient не прошёл frozen численную проверку. Не увеличивать tolerance по увиденным outcomes и не возвращаться молча к обычной модели.
3. При source lock mismatch сравнить pinned package versions и generator inputs. Изменять lock разрешается отдельным reviewed изменением с проверкой generated bytes; не добавлять автоматический update-lock в CI. При настоящем изменении данных нужен новый протокол, не продолжение прежней campaign.
4. При `robust_training_raw_scores_binding`, `selection_binding`, `summary_binding` или `persisted_material_changed` сохранить private campaign, считать результат недостоверным. Проверяются original requests/responses, model bytes, nonce, row order, выбранные corners и пересчитанные summaries. Нельзя переписывать expected hashes для получения pass.
5. При worker/image/ownership failure передать проблему operator. Проверить Docker Linux, source fingerprint и доступные ресурсы. Не применять global prune, reset SQL budget, отключение TLS или расширение privileges. Research action намеренно запрещена scoped publisher/scorer controllers.

Unit fault injections проверяют solver failure, NaN/неправильные dimensions, fake convergence, подмену output/nonce/rows, старый success report и отказ владения inherited workspace helper. Они не доказывают реальный hardware fault recovery. Native outcomes и clean-checkout evidence указываются отдельно.

Проверенная regression-проблема: Windows WinError 1314 не позволил создать symlink fixture соседнего intake test. Тест не пропущен: объединённая Linux suite выполнила 121 methods в non-root/read-only/network-none container. См. [RB-31](artifact-intake-troubleshooting.md) для разрешённого Linux replay, не выдавать Windows setup error за найденную модельную уязвимость.

## PB-19: воспроизведение в отдельном owned workspace

Prerequisites: Docker Linux amd64, pinned Python 3.12.15/uv 0.12.23, reviewed checkout. До окончания не менять source/scripts/lock и не переключать HEAD. Данные synthetic, сеть workers отключена. Final holdout не оценивается, SQL ledger и working cluster не используются.

```powershell
uv sync --locked --no-build --python 3.12.15
uv run --locked python -m unittest scripts.robust_training_qualification scripts.robust_training_native_qualification
uv run --locked python -m mlsecops build
uv run --locked python -m mlsecops bootstrap --state .runtime/robust-training-replay-20261013
uv run --locked python -m scripts.robust_training_native --state .runtime/robust-training-replay-20261013
```

Последние три команды изменяют состояние: создают image, lab keys/workspace и новые UUID campaigns. Не использовать чужой nonempty directory. Повтор запуска сохраняет новую campaign, не перезаписывает предыдущие primary materials; latest evidence показывает последний outcome. Exit 1 означает fail, exit 2 inconclusive; ни один не разрешает promotion. После завершения ожидаются 14 workers, две independent intake receipts, две parity проверки по 3000 rows, по 12 abstentions без inference и 47 проверенных primary files.

## Восстановление и rollback

Четыре controlled review findings исправлены до публикации: пустой/неполный abstain output не может сообщить 12 успешных fixtures; training/intake evidence перепроверяется семантически, не только по hash; cleanup timeout выдаёт sanitized incomplete/fail вместо traceback; точная десятичная граница AP loss=0.03 не отклоняется из-за subtraction rounding. Новые negative tests проходят, solver/thresholds не ослаблены. Linux regression после изменений: 125 methods pass; math-core coverage 100%, не orchestrator coverage.

Если процесс оборвался, сохранить unfinished campaign и устранить установленную runtime-причину. Повтор допустим с тем же frozen протоколом, не со случайно выбранным новым seed. При statistical failure остановить adoption и запросить новый обоснованный design review; не ретраить ради улучшения метрик. Наблюдавшиеся probes после публикации больше не untouched.

Baseline action и существующие grants не меняются, поэтому возвращать production model здесь не требуется. При functional regression откатить reviewed code increment обычным новым commit, собрать source-bound image и повторить в новом workspace; не удалять evidence. Такой rollback пока является процедурой, не выполненным production recovery. Даже успешный research candidate требует отдельного adoption decision, poisoning/M07 requalification и полной release/serving приёмки. Escalation: model reviewer для utility/robustness, operator для ownership/material/runtime failures. Safe fallback - ручной review без ML, а не отключение deterministic gates.
