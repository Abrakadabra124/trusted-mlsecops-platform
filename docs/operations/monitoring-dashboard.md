# T18: операторская панель мониторинга

Панель показывает состояние существующего monitoring runtime. Это интерфейс
только для чтения: он не запускает обучение, не меняет labels и не разрешает
promotion. Synthetic CPU профиль и ограничения общей R1 остаются в силе.

## Компоненты и доступ

FastAPI отдаёт три фиксированных ресурса: `/monitoring/ui`, `/monitoring/ui.css`
и `/monitoring/ui.js`. HTML задаёт структуру, CSS отвечает за отображение на
разных размерах экрана, JavaScript получает и проверяет снимок `/monitoring`.
Новые серверы, npm-пакеты и отдельная база данных для панели не нужны.

Оболочка публична и не содержит состояния сервиса или ключей. Маршруты панели
устанавливаются только при настроенном monitoring runtime и ключе оператора.
Данные по-прежнему требуют существующий operator bearer, который используется
для `/metrics` и `/monitoring`; ключ клиента inference к ним доступа не даёт.
Панель не расширяет права оператора. В частности, наличие JSON API не означает
доверие к произвольным присланным меткам.

Оператор открывает `http://127.0.0.1:<порт-сервиса>/monitoring/ui` существующего
разрешённого стенда и вводит его ключ оператора. Не помещать ключ в URL,
скриншот, тикет или командную строку. Поле сразу очищается, ключ остаётся в памяти
контроллера вкладки до отключения или перезагрузки. Приложение не пишет его в
cookies, localStorage или sessionStorage. Расширения браузера и администратор
хоста находятся за пределами этой гарантии.

HTTP разрешён только в существующем loopback лабораторном профиле. Это не
готовая конфигурация внешнего доступа: для удалённого размещения необходим
отдельно проверенный TLS и входной контур. Не открывать текущий порт в интернет.
Данный ранбук не разрешает запускать локальные Docker, WSL, Kubernetes или SQL.

## Что означают показатели

- Состояние сбора и health описывают доступность телеметрии, а не качество модели.
- Наблюдения считаются после завершённого успешного HTTP inference. Последние
  20 окон и до 8 квитанций на экране относятся к текущему процессу.
- PSI (Population Stability Index) измеряет сдвиг распределения относительно
  фиксированного reference. Показаны шесть признаков и предсказания отдельно.
  Число сохраняется полностью; визуальная шкала ограничена единицей.
- `null` в PSI означает недостаток наблюдений в этом ряду. Это не нулевой сдвиг
  и не сбой API. При abstention предсказание может быть недостаточным, когда
  распределения признаков уже оценены.
- Recall - доля верных положительных предсказаний среди положительных меток.
  Порог достаточности и сигнал деградации берутся из серверного контракта;
  арифметическое значение само по себе не подтверждает достаточную выборку.
- Reference digest и epoch позволяют сопоставить снимок с конкретным запуском.
  `history_restored=false` явно означает, что история процесса не восстановлена.

Снимок обновляется каждые 5 секунд. Один запрос ограничен 5 секундами, включая
чтение тела, и 256 KiB. Ответ должен соответствовать версии, типам, конечным
спискам и reference. Ошибочные данные не попадают в DOM; тексты записываются
через `textContent`, без HTML-интерпретации. Content Security Policy запрещает
сторонние источники, inline scripts, frames и отправку обычной HTML-формы.
Ответы имеют `no-store`, `nosniff` и `no-referrer`.

## Ранбук: диагностика без изменения runtime

Ответственный: оператор стенда. Сначала записать время, URL без параметров,
статус соединения, revision сервиса и, если доступен, reference/epoch. Не
публиковать bearer, сырые ответы, логи или подписи. Не менять release policy.

| Симптом | Проверка и действие | Условие восстановления |
| --- | --- | --- |
| Страница 404 | Проверить, что открыт правильный порт и в этом deployment настроен monitoring. В режиме без monitoring маршрут отсутствует намеренно | Из разрешённого deployment получена оболочка; не включать monitoring вслепую |
| Доступ отклонён | Проверить источник ключа и роль. После 401 панель очищает ключ и прекращает опрос | Один вход действующим operator bearer получает снимок; client bearer продолжает получать 401 |
| Лимит запросов | Закрыть лишние вкладки, не нажимать обновление многократно. API использует общую квоту оператора | Автоматическая попытка через 30 секунд успешна; квоту не отключать |
| Нет проверяемого состояния | Проверить доступность того же origin, статус `/monitoring` в Network без копирования Authorization и совпадение версии сервиса | Новые данные проходят проверку, старые значения не остаются зелёными |
| Система сообщает о проблеме телеметрии | Валидный 503 отображает состояние и конечные fault-коды. Применить [ранбук мониторинга](model-monitoring.md) и [перезапуска](monitoring-restart.md) | Не только HTTP 200, но и здоровый scheduler, завершённая доставка и актуальный epoch |
| Недостаточно данных | Проверить число наблюдений, abstentions и положительных меток. Не заменять `null` на ноль и не снижать порог | Достаточная разрешённая выборка и новое завершённое окно |
| История не восстановлена | Это ожидаемая граница текущего runtime, а не гарантия сохранения истории | Следовать процедуре нового epoch; не заявлять восстановление потерянных окон |

После сетевой ошибки панель удаляет прошлые значения и повторяет запрос через
10 секунд. При невалидной схеме действует так же. Поздний ответ предыдущего
подключения не может заменить данные новой сессии. «Отключить» прекращает опрос,
отменяет собственный запрос и таймеры, удаляет ключ и отображаемые данные.

## Плейбук проверки изменения

На чистом checkout использовать зафиксированные Python-зависимости и Node.js
20 или новее для исполнения JavaScript-тестов. Node нужен только проверкам,
серверный образ от него не зависит. Локально проверен Node v24.19.0; фактическая
версия hosted runner печатается в CI. Отсутствующий Node приводит к failure,
а не skip.

```text
uv sync --locked --no-build --python 3.12.15
node --version
uv run --locked python -m unittest scripts.monitoring_dashboard_qualification scripts.monitoring_privacy_qualification scripts.audit_http_observation_qualification
uv run --locked python scripts/check_docs.py
```

Это controlled/loopback проверки. Они не запускают контейнеры или SQL и не
заменяют hosted M13/M15 на фактическом candidate. JavaScript проверяется в
Node VM с контролируемыми DOM, fetch и временем: контракт, ошибки, 401/429,
таймаут заголовков и тела, oversized response, переподключение и очистка.
Настоящий браузер проверяется отдельно: вход, вывод показателей, узкий экран,
отказ с неверным ключом, отключение и перезагрузка.

Для candidate использовать существующие `kubernetes-privacy.yml` и
`kubernetes-monitoring.yml` на том же revision. В M13 девять чтений оболочки
с проверочными маркерами проходят внутри capture stdout/stderr/logs и audit scan.
Допускаются только точные байты трёх ресурсов или пустой 400 на query string.
Случайный другой маршрут, изменённая оболочка и неизвестные заголовки не могут
быть скрыты исключением audit ledger. Метрики сохраняют конечные 69 рядов.
Нужны terminal success, подтверждённая очистка disposable ресурсов и повторная
проверка первичных evidence после cleanup.

## Обнаруженные проблемы и границы доказательств

При разработке 2026-11-07 реальный браузер отклонил корректный снимок после
появления неполного окна: клиент требовал числовой PSI для всех рядов. Причина
воспроизведена тестом на отчёте настоящего evaluator. Исправление принимает
`null` только вместе с соответствующим `insufficient` и показывает отсутствие
оценки. Второй regression test выявил остающийся deadline при отключении
зависшего запроса; отключение теперь очищает его явно.

Локальный связанный набор: 37 tests, 0 skips. Панель и probe: 55 statements и
26 branches, 100% покрытия каждого модуля. В браузере на контролируемом predictor
наблюдались 12000 HTTP observations, 12 окон, 200 положительных меток и 3 signed
receipts; это не отдельная приёмка actual ONNX candidate. Desktop и узкий экран
проверены, ширина страницы на узком экране совпала с client width (375 px).
Оба временных стенда завершены штатно, принадлежащие им порты закрыты.

[Hosted проверка 6fa4d96](../evidence/monitoring-dashboard-2026-11-07.md) завершена:
M15 188 criteria, M13 512 criteria и 9 static privacy requests, cleanup и
post-cleanup replay подтверждены. Node hosted v22.23.4, contracts350Linux
executions/0skips. На чистом checkout37tests/0skips. Общий R1 остаётся открытым;
дальше T29/M23. Разные candidate references M13/M15 не являются общей M18 acceptance.
