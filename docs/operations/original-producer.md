# Исходный кандидат на hosted producer

Два шага выполняются в **одной попытке задания producer** на одном GitHub-hosted Ubuntu 24.04 x86_64. Перед первым шагом контроллер принимает публичный образ из задания сборки, проверяет его идентификатор, метки источника и контрольные суммы архива. Чистый checkout, публичный запуск и идентичность образа сверяются снова при подготовке кандидата. Оригинальный ключ доверия оператор подаёт защищённым файлом вне checkout.

```console
.venv/bin/python -B -W error -m scripts.ci_original_bootstrap prepare
.venv/bin/python -B -W error -m scripts.ci_original_publish publish
```

| Шаг | Входы процесса | Что проверяется |
|---|---|---|
| Оба | `CANDIDATE_PUBLIC_TOKEN`, `SOURCE_IMAGE_RECEIPT` | Токен чтения метаданных публичного запуска и квитанция точного образа из этой попытки. |
| `prepare` | `CANDIDATE_TRUST_FILE` | Существующий защищённый файл Ed25519 вне checkout. Тот же ключ участвует в проверке потребителями. |
| `publish` | `CANDIDATE_STORE_WRITE`, `CANDIDATE_TRANSFER_KEY` | Отдельный издатель приватного репозитория и 32 байта ключа транспорта в каноническом Base64. |
| `publish` | `CANDIDATE_JOURNAL_RELEASE`, `CANDIDATE_JOURNAL_PUBLIC`, `CANDIDATE_JOURNAL_KEY_FILE`, `CANDIDATE_ORIGIN_RELEASE` | Операторские дескрипторы двух отдельных приватных релизов, исходный открытый ключ журнала и защищённый файл его закрытого ключа. |

## От данных до публикации

1. `prepare` резервирует идентичность рабочей области для одной попытки, создаёт состояние с исходным ключом доверия, проверяет ресурсы runner и использует закреплённые версии инструментов. Для Kubernetes нужны минимум 4 CPU, 15 ГиБ памяти Docker и 12 ГиБ свободного места.
2. После подготовки собственного кластера и SQL вызываются штатные M01 и M02. Контроллер фиксирует начало M21. Затем M07 вызывает необходимый путь M03 и оценивает обученного кандидата. Проверяются ссылки на датасет, кандидата и оценку в отчётах и в исходной записи контроллера.
3. Для передачи подготовленного состояния временный кластер закрывается. Контроллер сверяет сохранённую идентичность SQL. Весь следующий шаг использует ту же рабочую область и исходный кандидат.
4. `publish` проверяет подготовленное состояние, фиксирует исходное предложение, создаёт пакеты для обеих ролей и вызывает штатную публикацию с контрольной записью после каждого изменения приватного хранилища. Подписанный журнал открывается заново по ожидаемой последней записи.
5. Рабочие объекты нужны обоим потребителям. Пять исходных зашифрованных файлов сохраняются также в отдельном приватном релизе. Копии читаются и сверяются до передачи управления потребителям. Сроки исходных предложений продолжают отсчитываться во время передачи.
6. Открытый ключ проверки исходного документа передаётся потребителям через доверенный выход producer. Для удаления рабочей копии терминальный контроллер использует отдельный архив исходных файлов, журнал и результаты обоих потребителей. [Регламент завершения](ci-campaign-terminal.md), [восстановление результатов](ci-primary-recovery.md).

## При отказе

| Сбой | Что сохранить и проверить |
|---|---|
| Разошлись образ, SHA, попытка или характеристики runner | Проверить исходную квитанцию образа, идентичность текущего задания и доступные ресурсы до обучения. |
| M01, M02 или M07 вернул отказ | Сохранить закрытые отчёты в приватном контуре. Проверить владельца кластера и SQL, результат очистки и фактическую остановку исходного SQL. |
| Не подтверждено очередное изменение приватного хранилища | Использовать подписанные записи частичного журнала и независимые чтения по ID. Построение нового предложения создаёт другую попытку. [Ранбук журнала](ci-campaign-journal.md). |
| Истёк срок предложения либо не прошёл контрольный replay | Сохранить исходные свидетельства. Историческое чтение доступно по подписанным данным. Допуск потребителя требует действующих сроков исходного предложения. |

Локальные тесты проверяют вызовы штатных компонентов и обработку отказов на контролируемых границах SQL, Kubernetes и сети. Из корня checkout можно повторить проверки командой

```console
uv run --locked python -B -W error -m unittest scripts.ci_original_bootstrap_qualification scripts.ci_original_publish_qualification scripts.ci_origin_backup_qualification scripts.ci_terminal_primary_qualification
```

Живая приёмка требует полного прогона producer и обоих потребителей на одном кандидате.
