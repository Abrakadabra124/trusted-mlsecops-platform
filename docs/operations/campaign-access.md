# Временный доступ T21 к приватным файлам релиза

Задания кампании работают на стандартном `ubuntu-24.04` в публичном `Abrakadabra124/trusted-mlsecops-platform` (ID `1407811916`). Зашифрованные пакеты хранятся в релизах приватного `Abrakadabra124/trusted-mlsecops-ci-private` (ID `1465012664`). Встроенный `GITHUB_TOKEN` ограничен исходным репозиторием. [Контракт кампании](../superpowers/specs/2026-11-20-candidate-cross-job-design.md), [граница GITHUB_TOKEN](https://docs.github.com/en/actions/concepts/security/github_token).

| Среда в публичном репозитории | Единственный секрет хранилища в среде | Contents в приватном репозитории | Кто использует |
| --- | --- | --- | --- |
| `candidate-store-read` | `CANDIDATE_STORE_READ` | Read-only | Задание потребителя скачивает пакет |
| `candidate-store-write` | `CANDIDATE_STORE_WRITE` | Read and write | Отдельные задания публикации и очистки |

## Оператор готовит и проверяет доступ до выпуска токенов

Эти настройки оператор может применить через GitHub API из уже разрешённой сессии владельца. Для них токены хранилища не нужны. [API правил веток](https://docs.github.com/en/rest/deployments/branch-policies).

1. В административной сессии владельца публичного репозитория открыть **Settings > Environments**. Создать обе среды без секретов. В каждой выбрать **Selected branches and tags** и добавить ровно одно правило типа **Branch** с именем `qualify/candidate-cross-job`. Сверить сохранённые правила обеих сред. Список тегов пуст. На GitHub Free эти настройки доступны в публичном репозитории. Режим **Protected branches only** при отсутствии защищённых веток допускает все ветки. [Настройка сред](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments), [правила допуска](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments).
2. Проверить workflow и вызываемые скрипты на полном SHA коммита. Закрепить внешние actions полным SHA. Любой workflow разрешённой ветки может запросить среду и прочитать её секрет. Проверить все такие задания и триггеры. Защитить ветку от непроверенных изменений, включая обход администратора. Для ручного запуска можно зафиксировать проверенный коммит правилом **Lock branch**. Сверить ID исходного репозитория, точную ветку и SHA запуска. Обычный `pull_request` из форка не получает эти секреты. Исключить исполнение кода из pull request в привилегированных заданиях, включая `pull_request_target`. Передавать токен только шагу работы с хранилищем. [Защита ветки](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches), [безопасность workflow](https://docs.github.com/en/actions/reference/security/secure-use).
3. Если задан **Required reviewers**, проверить, кто сможет разрешить задание. Достаточно одного назначенного пользователя или участника назначенной команды с доступом от Read к публичному репозиторию. При **Prevent self-review** инициатор запуска одобрить его не может. При требовании независимого одобрения выключить обход администратора. Без второго проверяющего такой запуск останется в ожидании. [Правила одобрения](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments#required-reviewers).
4. Проверить границу подписи. Право записи действует на содержимое всего выбранного репозитория. Утечка токена позволяет заменить или удалить доступные для изменения файлы релиза. Для проверки управляющей записи потребитель должен получить открытый ключ напрямую из выхода доверенного задания `producer` той же попытки и сверить подпись, SHA источника, запуск, попытку и фазу. Одноразовый закрытый ключ остаётся у производителя. Одного токена записи для новой подписи недостаточно. Код задания, которое создаёт подпись, остаётся доверенным. Приватные пакеты и их контрольные суммы не выводить в публичные логи, результаты шагов или артефакты. [Права на файлы релиза](https://docs.github.com/en/rest/releases/assets).

## Владелец выпускает и вводит два токена

После проверки оператором владелец открывает **Settings > Developer settings > Personal access tokens > Fine-grained tokens**. Для каждой строки таблицы создать отдельный токен. У обоих выбрать **Resource owner** `Abrakadabra124`, **Only select repositories** и только `trusted-mlsecops-ci-private`. Задать Contents по таблице. GitHub добавляет **Metadata read** автоматически. Остальные настраиваемые права оставить выключенными, включая Actions, Workflows и Administration. Выбрать кратчайший срок, покрывающий запуск и очистку, например один день, если этого достаточно. [Выпуск и отзыв токенов](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).

Каждое значение ввести в скрытом интерактивном запросе своей локальной консоли с отключённой записью и отладкой. Команды содержат только имена. Значение не передавать в аргументах, через команду оболочки, в логах или чате. [Справка GitHub CLI](https://cli.github.com/manual/gh_secret_set).

```powershell
gh secret set CANDIDATE_STORE_READ --env candidate-store-read --repo Abrakadabra124/trusted-mlsecops-platform
gh secret set CANDIDATE_STORE_WRITE --env candidate-store-write --repo Abrakadabra124/trusted-mlsecops-platform
```

## Оператор проверяет и закрывает доступ

- Сверить имена через `gh secret list` для каждой среды с теми же `--env` и `--repo`. Затем на одноразовом тестовом файле проверить ID и приватность хранилища, запись издателем, чтение потребителем, отказ записи с читающим токеном и очистку. До этих проверок передачу кандидата считать неподтверждённой.
- После завершения или отмены дождаться остановки всех заданий этой попытки. Сохранить и проверить приватную копию обязательных свидетельств. Удалить только временные объекты с подтверждёнными ID релиза, запуска и попытки. Проверить ответ 404 по удалённым ID и отсутствие объектов в доступном списке.
- Владелец отзывает оба токена в **Fine-grained tokens**. Оператор удаляет оба секрета из соответствующих сред и проверяет списки повторно. При подозрении на утечку токен отозвать немедленно, остановить запуск и сверить целостность приватных материалов до возобновления.
