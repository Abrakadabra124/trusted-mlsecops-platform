# ADR-002: Доверять связанному release bundle, а не model registry alias

Дата: 2026-10-06. Статус: **Proposed**, до прототипа T13 и проверки формата.

## Контекст

Модель зависит от preprocessing, схемы входа, окружения, данных и результатов оценки. Изменяемый alias в registry не подтверждает, что эти части согласованы, а подпись отдельного model file не связывает его с независимым report.

## Решение

Единица выпуска - immutable ModelReleaseBundle с digest материалов и runtime, отдельными подписями/approval, policy digest, environment scope и сроком действия. Candidate не получает serving-доступ до проверки promotion policy. Loader повторяет проверку до load и соблюдает trust lease. Rollback требует действующего разрешения и совместимости всего комплекта.

## Альтернативы

- `models:/name@champion`: удобно для экспериментов, но alias меняется, поэтому не является корнем доверия.
- Только подписанный контейнер: защищает image bytes, но не внешний скачиваемый model file и не происхождение оценки.
- Только DB-запись approval: удобна для поиска, но требуется защищённая привязка к digest и контроль переходов.

## Последствия и пересмотр

Появляются verifier, policy lifecycle и управление ключами. Нельзя скрыть эту стоимость, называя JSON manifest готовой защитой. Необходимо избежать circular hashes, неоднозначного JSON и TOCTOU. После T13 выбрать версионированный envelope и закрепить тесты interop; если стандартный attestation format закрывает потребности, не изобретать собственную криптографию. Центральный принцип binding всех материалов сохраняется.
