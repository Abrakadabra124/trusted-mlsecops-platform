# ADR 0065: периодическое наблюдение за отзывом доверия

Статус: принято для реализации обязательной T29/M23. Полный R1 остаётся открыт.

## Требование и решение

Ручной `security_trust_events` уже проверяет подписанную SQL-историю, доставляет
события через durable outbox и восстанавливается после пропуска запуска. Для
эксплуатации нужен постоянный процесс: отзыв должен обнаруживаться без команды
оператора, а недоступность SQL не должна маскироваться heartbeat.

Добавляем `python -m mlsecops.security_trust_service --config ABSOLUTE_PATH`.
Процесс фиксирует digest конфигурации, запускает один собственный child
`security_trust_events` сразу и затем каждые 30 секунд по monotonic clock.
Проверка ограничена 10 секундами; stdout/stderr child направлены в DEVNULL.
Heartbeat отправляется самим child только после полной проверки истории,
проекции outbox и подтверждения доставки всех событий. HTTP echo heartbeat
не является подписанным разрешением promotion.

Процесс держит существующий POSIX lock на отдельном приватном каталоге своей
конфигурации. Второй supervisor этого каталога отвергается. SIGTERM/SIGINT
останавливают admission новых проверок; текущий child terminate/kill/reap
ограничен двумя секундными ожиданиями. Неподтверждённая очистка завершает
supervisor с ошибкой. Никаких потоков, очередей, shell или новых зависимостей.
Повтор не меняет event ID/epoch, не очищает outbox и не выдаёт release grant.

## Альтернативы и границы

- Cron/systemd timer потребовал бы отдельного scheduler и контроля наложения
  запусков. Собственный CLI использует существующий Python runtime и явно
  владеет дочерним процессом.
- Постоянный heartbeat в независимом sidecar скрывал бы зависший SQL reader.
  Поэтому heartbeat связан с успешной проверкой source, а не с жизнью родителя.
- Блокирующий SQL в collector ухудшил бы приём событий от остальных producers.
  Наблюдатель остаётся отдельным доверенным процессом с существующим `ml_serving`
  SELECT/TLS доступом, без изменения SQL grants.

Нужны schema2 outbox и отдельный trust producer с heartbeat_required=true в
подписанном registry. Старые ручные CLI без heartbeat сохраняют прежний контракт.
Приватный каталог/config/mounts принадлежат оператору; host-admin rollback,
злонамеренный оператор и произвольные дочерние деревья не входят в защиту.
Child выполняет только собственный модуль, не запускающий grandchildren.
Локальный loopback transport не расширяется до незащищённого сетевого адреса.
Развёртывание всех producers, фактические mounts/network и общий M23 ещё нужны.

## Проверка

Отрицательные тесты: подмена config до SQL/IO, SQL/history/outbox/delivery failure
без heartbeat, зависший child, failure spawn, stop во время запуска/ожидания,
неподтверждённая очистка, второй supervisor, privacy вывода. Native hosted Linux:
реальный SQL commit при запущенном supervisor, receipt/route <=60s, отсутствие
дубликатов, collector outage и recovery того же события, остановка supervisor
и подписанный gap <=120s. Проверять реальные интервалы, source и очистку.
